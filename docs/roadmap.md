# План Suveren

Договорились 31.10.2026 после выпуска 1.1.0. План собран из старого плана и независимого
ревью, сверенного с кодом. Порядок: сначала инструмент не должен вредить тому, кто его
запускает, потом не должен врать в отчётах, и только потом растёт.

Обозначения: ✅ сделано, ⏳ в работе, ⬜ не начато.

## Правила для всех версий

- Одна версия — одна ветка и один PR.
- Слияние в `main` только при зелёном CI и с OK владельца. `main` защищён: только через PR и
  только с шестью зелёными проверками CI.
- Выпуск: поднять версию в `pyproject.toml`, поставить тег `vX.Y.Z`. Exe в Releases и пакет
  на PyPI публикуются сами. Публикация на PyPI необратима.
- Каждое исправление — отдельным коммитом с тестом. Запись в CHANGELOG — отдельным коммитом
  `CHANGELOG: ...`.
- Если меняется ответ проверки, нужен случай на полигоне и прогон записанных реальных сайтов.
- Перед слиянием раздела с новым видом отчёта владелец смотрит HTML-отчёт.
- Прогон записанных реальных сайтов (corpus) делается локально, у владельца: из облака
  сайты и российские источники открываются не все.
- После каждого пункта, по возможности, — отдельный агент-ревьюер со свежим контекстом:
  читает diff пункта и ищет баги, ложные срабатывания и юридические неточности.

## 1.1.1 — безопасность самого инструмента ✅ выпущено 31.10

Враждебный сайт не должен навредить тому, кто его проверяет.

- Защита от SSRF: запросы только на публичные адреса, проверяется каждый шаг
  перенаправления, соединение открывается с проверенным адресом (подмена DNS не проходит).
  Карта сайта берётся только со сканируемого сайта.
- Лимит 10 МБ на ответ, до распаковки и после неё; gzip-бомба не проходит.
- Адреса из сертификата (выдавший центр, OCSP, CRL) проходят ту же проверку.
- Браузер: запросы на внутренние адреса обрываются, загрузка файлов отключена.
- Exe и Docker-образ собираются из зависимостей, закреплённых по хешам.
- Отчёт с плагинами помечен в HTML, JSON и SARIF (схема JSON 1.8).
- Блокировки: настоящий источник — «antifilter.download, выгрузка от ДД.ММ».
- SECURITY.md переписан: модель угроз, честное описание каждого режима, сообщать об
  уязвимостях через Report a vulnerability на GitHub.
- Мелочи: поиск ключей в скриптах обрезается по любому `</script ...>`; ночной прогон
  сравнивается с последним настоящим прогоном.

## 1.1.2 — честность ✅ готово к выпуску

Отчёт не должен обещать больше, чем на самом деле проверено. Ветка `1.1.2-honesty`.

### 1. Хвосты 1.1.1 ✅

- Браузер выходит в сеть только через встроенный прокси: подмена DNS и WebSocket больше не
  проходят мимо проверки. UDP для WebRTC мимо прокси запрещён.
- TLS-рукопожатие с сайтом и WHOIS идут только на проверенные адреса.
- В SECURITY.md исправлен неверный текст про `HTTPS_PROXY`.

### 2. Исправления по второму ревью, по важности

1. ✅ ИНН: формат «ИНН/КПП», «ИНН (КПП)», «ИНН организации»; ИНН банка или платёжного
   сервиса больше не обгоняет ИНН владельца.
2. ✅ PD-008: HTTPS не ответил вовремя — «не проверено», а не «сайт без HTTPS» (kremlin.ru).
3. ✅ Поддомены: после пустого ответа crt.sh спрашивается Cert Spotter; сбой DNS у
   поддомена не даёт предупреждения о захвате.
4. ✅ Надёжность: плагин с `sys.exit()` или зависанием не роняет скан; загружаются плагины с
   `@dataclass` и `from __future__ import annotations`; ошибки Playwright превращаются в
   понятное сообщение, браузер закрывается; распаковка gzip в проверке утечек из форм
   ограничена.
5. ✅ Точность:
   - moment.js 2.10–2.19.2: Suveren пишет «уязвимостей нет», хотя для этих версий есть CVE;
   - CSP с `default-src 'self'` без `object-src` ошибочно считается слабой;
   - пороги срока сертификата 14 и 30 дней абсолютные, и короткоживущие сертификаты
     получают ложную ошибку. Нужна дата выпуска сертификата.
6. ✅ Мелкие:
   - DMARC без `p`, но с `rua`: по RFC это `p=none`, а у нас была ошибка; заодно
     `p=reject` с неверным `sp=` без `rua` больше не считается защитой;
   - флаг «Edge case» из базы захвата поддоменов читается и попадает в отчёт;
   - удаляемые cookies, счётчики аналитики и `author` больше не «сессионные»;
   - MTA-STS: отсутствие — заметка, а не предупреждение; ошибка политики названа;
     таймаут — «не проверено»;
   - самопроверка отчёта охраняет правила расчёта оценок;
   - в SARIF есть общая оценка;
   - предупреждение SPF при DMARC `reject` — низкой срочности;
   - `Suveren.bat` проверяет версию Python;
   - тесты плагинов покрывают реальные сбои. Нашлись две ошибки: любой упавший плагин
     ронял весь отчёт, а `KeyboardInterrupt` из плагина — весь скан.

### 3. ✅ Две метки у каждой проверки

- Что она делает с сайтом: не обращается, только смотрит, прощупывает (TLS 1.0/1.1,
  страницы поддоменов) или вводит данные (`--form-leaks`).
- Чем рискует тот, кто запускает: сайт вас не видит, видит ваш IP или выполняется
  JavaScript сайта.

Метки в каталоге, `suveren checks`, `docs/checks.md` и SARIF. README переписан: раздел «Что
Suveren делает с сайтом» по режимам запуска.

### 4. ✅ Источник и дата у каждого реестра

Блокировки, санкционные списки (у каждого своя дата выгрузки), ЕГРЮЛ, реестр операторов ПДн,
журналы сертификатов, Team Cymru, встроенные базы уязвимостей и захвата поддоменов (дата
сверки). В доказательствах проверки, в отчёте о компании — строкой «Источник».

### 5. ✅ Файл исключений `.suveren-ignore`

Строка: ID, сайт, срок, автор, причина. Принятая проблема видна в отчёте, но не входит в
приоритеты, оценку и пороги CI; в SARIF — `suppressions`. После срока снова учитывается.

### 6. ✅ Проверка на случайных данных

SPF (с обходом include и redirect), DMARC, MTA-STS, CSP, Set-Cookie и карта сайта на мусоре
(Hypothesis, `tests/test_fuzz.py`): в CI по 200 примеров, прогон на 10 000 чистый. Нашлась
одна ошибка: битая строка `Sitemap:` в robots.txt роняла весь скан.

## 1.1.3 — срочное по ревью ✅ готово к выпуску

Исправления по внешнему ревью версии 1.1.2. Ветка `1.1.3`.

1. Песочница браузера: Chromium запускается с песочницей (`chromium_sandbox=True`), как
   обещает SECURITY.md; в Docker — не от root, иначе песочница не стартует.
2. Управляющие символы с сайта: C0/C1 (кроме перевода строки и табуляции) и символы
   направления текста вырезаются до попадания в проверку; разметка Rich в терминале
   экранируется. Иначе сайт мог подменить буфер обмена (OSC 52).
3. Лимит числа и размера записей `__suverenKeep` в эксперименте с формами на стороне Python.
4. TLS: сертификат не проверен, а TLS 1.0/1.1 неизвестны — «не проверено», а не «в порядке»;
   в отчёте сказано, что проверка TLS поверхностная.
5. CO-007: WHOIS скрыт или ЕГРЮЛ не ответил — «не проверено», а не «в порядке».
6. Штрафы: PD-007 и LAW-001 условные, в итоговую сумму не входят, показываются отдельно.
7. Неверные фразы: `--dns ru`, «честный User-Agent», «в кеше только общедоступные списки»
   (и лимит размера `unknown-hosts.json`), «реестр РКН» в README.
8. `--pdf` на Windows: адреса `file:`, `data:`, `about:` не блокируются; тест не пропускается,
   если браузер установлен.
9. Public Suffix List (с приватной секцией) вместо своего `registrable_domain`: сайт на
   tilda.ws, github.io, narod.ru — не почта и не поддомены платформы.
10. Мелочь: регулярка `</\1>` в subdomains.py; meta Content-Security-Policy в HTML-отчёте.
