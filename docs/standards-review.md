# Сверка проверок со стандартами (блок 1b)

Начата 2026-10-22. Здесь записано, где проверка расходилась со стандартом и что
исправлено. Таблица точности по полигону будет добавлена отдельным разделом.

## Почта

| Проверка | Стандарт | Расхождение | Исправление |
|---|---|---|---|
| MTA-STS (SUV-MAIL) | RFC 8461, разд. 3.3 | Файл политики читался с переходом по редиректам, а отправители по ним не переходят: политика за редиректом для них не существует, а Suveren её засчитывал | Политика читается без редиректов (b4ca18a) |
| MTA-STS | RFC 8461, разд. 4.1 | В режиме enforce не сверялись MX-серверы со строками `mx:` политики. Если MX там нет, отправители вроде Gmail на него не доставят письма, а проверка ставила OK | Такой случай теперь FAIL, с названием серверов; шаблон `*.` совпадает ровно с одной меткой (b4ca18a) |
| SPF | RFC 7208, разд. 6.1 | `redirect=` рядом с `all` не применяется, но учитывался в лимите DNS-запросов и проходился | Игнорируется (818214f) |
| SPF | RFC 7208, разд. 5.5 | Механизм `ptr` («SHOULD NOT be used») не отмечался | Предупреждение и совет заменить на `ip4:`/`a:` (818214f) |
| SPF | RFC 7208, разд. 4.6.4 | Лимит 10 DNS-запросов: совпадает | — |
| DMARC | RFC 7489, разд. 6.3, 6.6.3 | `p` обязателен, `sp` наследует `p`, несколько записей означают отсутствие DMARC: совпадает. Поиск записи организационного домена не нужен: почта проверяется по зарегистрированному домену | — |

Не сделано: лимит «пустых» DNS-ответов в SPF (не больше 2, RFC 7208, разд. 4.6.4);
проверка поля `id=` и единственности TXT-записи `_mta-sts` (RFC 8461, разд. 3.1).

## Веб

| Проверка | Стандарт | Расхождение | Исправление |
|---|---|---|---|
| TLS-сертификат | Проверка браузера: цепочка до доверенного корня, имя, сроки (RFC 5280, RFC 6125) | Самоподписанный сертификат, сертификат на другое имя или с недоверенным корнем получали OK, была только заметка внизу отчёта. На badssl.com: self-signed, wrong.host, untrusted-root давали OK | Отдельное рукопожатие с проверкой, как в браузере. Ошибка даёт FAIL с понятной причиной; сертификат НУЦ Минцифры даёт WARN с советом поставить второй сертификат. Заметка о недоверенном сертификате убрана из отчёта, когда эта проверка выполнена, чтобы не повторяться. Перепроверено на badssl.com: expired, self-signed, wrong.host, untrusted-root дают FAIL; sberbank.ru (НУЦ Минцифры) даёт WARN |
| TLS-протоколы | RFC 8996 (2021) | Отказ от TLS 1.0/1.1 был обоснован общими словами «PCI DSS, NIST» | Добавлена ссылка на RFC 8996 и NIST SP 800-52 |
| X-Frame-Options | OWASP Secure Headers Project | `ALLOW-FROM` и любые значения кроме `DENY`/`SAMEORIGIN` современные браузеры игнорируют, а проверка их засчитывала | Засчитываются только `DENY` и `SAMEORIGIN` (или CSP `frame-ancestors`) |
| HSTS | RFC 6797; порог preload-списка | Минимум 180 дней, `max-age=0` выключает HSTS: совпадает | — |
| CSP | CSP Level 3 | `'unsafe-inline'` при nonce/hash игнорируется, при `'strict-dynamic'` игнорируются списки хостов: совпадает. Не учитываются `script-src-elem` и CSP из `<meta>` для `frame-ancestors` (там он не действует, и проверка его оттуда не берёт — верно) | — |
| Cookies | RFC 6265bis | `SameSite=None` без `Secure` браузеры отвергают: совпадает | — |
