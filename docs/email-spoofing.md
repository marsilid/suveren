# Можно ли подделать письмо от имени компании

Клиенту приходит письмо с настоящего адреса компании: «у нас поменялись реквизиты, оплатите
счёт сюда». Адрес верный, почтовая программа ничего подозрительного не показывает. Человек
платит, деньги уходят мошенникам.

Чтобы отправить такое письмо, ничего взламывать не нужно. Протокол почты позволяет написать в
поле «От кого» любой адрес. Защищают от этого три записи в DNS домена.

## Три записи, которые защищают почту

**SPF** перечисляет серверы, которым разрешено отправлять почту от имени домена. Запись вида
`v=spf1 include:_spf.yandex.net -all`. Окончание `-all` значит «остальным нельзя», `~all`
значит «остальным подозрительно».

**DKIM** ставит на каждое письмо цифровую подпись. Открытый ключ лежит в DNS под именем
`селектор._domainkey.домен`. Ключ короче 1024 бит считается слабым, лучше 2048.

**DMARC** говорит почтовым серверам, что делать с письмом, которое не прошло SPF и DKIM. Это
главная запись, без неё первые две почти не работают.

| Значение `p=` в DMARC | Что будет с поддельным письмом |
|---|---|
| записи нет | придёт во «Входящие» |
| `p=none` | придёт во «Входящие», владелец домена только получит отчёт |
| `p=quarantine` | попадёт в спам |
| `p=reject` | не дойдёт |

Когда мы проверили 284 сайта крупных российских компаний, у 275 запись DMARC удалось прочитать.
У 22 её не было вовсе, у 44 стояло `p=none`. Итого почти у четверти компаний поддельное письмо
спокойно доходит до получателя.

## Как проверить самому

В Windows откройте командную строку и введите:

```bash
nslookup -type=TXT _dmarc.ваш-сайт.ru
```

Посмотрите, что стоит после `p=`. `reject` хорошо, `quarantine` терпимо. Если там `none` или
запись не нашлась, передайте это администратору.

## Как проверить всё одной командой

[Suveren](index.md) проверяет SPF, DKIM, DMARC, MTA-STS и длину ключей, а в конце даёт простой
ответ: подделать письмо можно, можно частично или нельзя. На Windows скачайте
[Suveren.exe](https://github.com/marsilid/suveren/releases/latest) и введите адрес. Или из
командной строки:

```bash
pip install suveren
suveren scan сайт.ru --checks mail
```

Проверки почты читают публичные записи DNS. Только MTA-STS скачивает файл политики с поддомена
`mta-sts`, как это делает любой почтовый сервер.

Список DKIM-ключей домена снаружи не получить, поэтому Suveren пробует распространённые
селекторы. Свой селектор можно подсказать: он стоит в заголовке `DKIM-Signature` любого вашего
письма после `s=`.

```bash
suveren scan сайт.ru --checks mail --dkim-selector mail2024
```

## Как включить защиту и не сломать рассылки

1. Настройте SPF: перечислите в нём все сервисы, которые шлют почту от вашего имени. Это
   корпоративная почта, сервис рассылок, CRM, сайт.
2. Включите DKIM у каждого из этих сервисов, обычно это кнопка в настройках и запись в DNS.
3. Поставьте DMARC с `p=none` и адресом для отчётов `rua=mailto:...`. Пару недель смотрите
   отчёты: так видно, какой сервис вы забыли.
4. Когда в отчётах остались только чужие серверы, переключите на `p=quarantine`, потом на
   `p=reject`.

Если сразу поставить `p=reject`, можно случайно отправить в спам собственные рассылки и
письма из CRM.

Все проверки почты с ID `SUV-MAIL-*` есть на странице [Все проверки](checks.md).
