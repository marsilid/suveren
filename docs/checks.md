# Проверки Suveren

Файл создаётся командой `suveren checks --markdown > docs/checks.md` из каталога `src/suveren/catalog.py`. ID проверки не меняется между версиями: на него можно ссылаться в отчётах, задачах и правилах CI (`suveren scan сайт --checks ID`).

Статусы: **проблема** — нарушение или уязвимость найдены; **внимание** — возможная проблема, нужна ручная проверка; **не проверено** — данных не хватило (это лучше ложной тревоги); **в порядке**.

У каждой проверки две метки. **С сайтом** — что она делает с проверяемым сайтом:

- *не обращается к сайту* — только DNS, публичные реестры и журналы сертификатов.
- *только смотрит* — открывает страницы и файлы сайта, как посетитель, поисковый робот или почтовый сервер.
- *прощупывает* — делает запросы, которых обычный посетитель не делает: соединения по устаревшим TLS 1.0 и 1.1, страницы поддоменов.
- *вводит данные* — печатает тестовые значения в формы сайта и не отправляет их.

**Для вас** — чем рискует тот, кто запускает проверку:

- *сайт вас не видит* — запросы идут в DNS и публичные реестры, сайт о проверке не узнает.
- *сайт видит ваш IP* — как при обычном заходе: в журналах сайта останется ваш IP-адрес.
- *выполняется JavaScript сайта* — страница открывается в браузере на вашем компьютере, и её скрипты работают; браузеру закрыты внутренние адреса вашей сети и загрузка файлов.

Любой `suveren scan` открывает главную страницу сайта и читает его DNS: из них собираются иностранные сервисы. Поэтому сайт видит ваш IP при любом скане, даже если выбраны только проверки «не обращается к сайту». С `--browser` страницы открывает браузер, и JavaScript сайта выполняется у всех проверок, которые читают страницы.

## Иностранные зависимости

Находки об иностранных сервисах имеют ID по категории: `SUV-DEP-DNS`, `SUV-DEP-HOSTING`, `SUV-DEP-MAIL`, `SUV-DEP-CDN`, `SUV-DEP-ANALYTICS` и т. д. (`SUV-DEP-` и название категории). Они есть в JSON (`findings[].id`) и SARIF.
